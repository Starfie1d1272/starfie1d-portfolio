---
title: Broadcast 独立模式与 RivalHub 连接模式共用同一套 Runtime
date: 2026-09-17
context: RivalHub 可以提供完整的 Match、Roster、Steam64、BP、Schedule 和 Branding，但如果 Broadcast 只有连上 RivalHub 才能运行，它就会失去作为独立本地制播工具的产品价值。
decision: 产品只定义独立模式和 RivalHub 连接模式两种运行方式；两者共享 Runtime、identity、Radar、Program、Local Protocol 和 Lookahead 模型，只在 MatchContext 的来源上不同。
alternatives:
  - option: Broadcast 只做 RivalHub 附属工具
    pros:
      - 第一方集成最直接
    cons:
      - HUD / Radar / Program 无法独立使用
      - 把 Web / 数据库内部实现变成不必要的运行依赖
  - option: 为独立模式维护一套简化 Runtime
    pros:
      - 可以快速做一个“能跑”的轻量版
    cons:
      - 两套状态和 identity 模型迟早漂移
      - 相同故障语义需要维护两遍
reasoning: RivalHub 应该是最完整的 context provider，而不是 Core 的前置条件。独立模式只维护当前节目所需的最小比赛上下文，不复制 RivalHub 的长期 Team、报名、赛务后台等完整数据库。

这条决定把“谁会用”和“怎么运行”分开了：校园赛、社区赛、小型赛事是适用场景，不是第三种技术模式。
